# 软件断点

## 为什么是软件断点，不是硬件断点

x86 的硬件断点只有 4 个（调试寄存器 `DR0..DR3`），而且要抢目标的调试寄存器。
被分析的程序自己用（反调试）或别的工具占用时，我们**没有公平的协调机制**：
抢到了就是把别人挤掉，而那种失败会表现成"对方的工具莫名失效"。

软件断点没有数量上限，代价是改一字节代码（改完立刻改回）。

## 命中后**自动解除**（一次性的）

传统调试器的做法是"命中 → 恢复原字节 → 单步执行一次 → 重新写入 `0xCC`"。
那段舞蹈在**多线程目标**里是有竞态的：恢复原字节与重新写入之间，
别的线程可能正好执行到这条指令——它看到的是一半被改过的代码。

要安全地做这件事，必须先把目标的**所有线程停下来**。我们没有那个能力：
Pin 不是调试器，进程的线程由目标自己调度。

所以这里选的是一条**明确的语义**，而不是"看起来像调试器但会偶发崩目标"：

* 命中一次后断点**自动解除**，事件里带 `args[0] = 1` 标记；
* 想重复命中就再调用一次 `pb_set_breakpoint`——脚本可以这么做，
  而且这正是脚本相对固定工具接口的优势：**它自带状态**。

这条语义比"悄悄留下一个竞态"更可控，也更容易被 AI 正确使用：
它会在事件里明确看到"已解除"，而不是在某个时刻收到一个莫名其妙的崩溃。

## 地址打错不能把目标打崩

**这条是被实测逼出来的。** 把 `SetBreakpoint` 接到真实实现之后，
一条拿 `0x1000` 当"假地址"的老用例真的往 `0x1000` 写了 `0xCC`，
整个测试进程 `STATUS_ACCESS_VIOLATION`。

修法与内存读同一条纪律：**永不裸解引用调用方给的地址**。

* 读原字节用 `ReadProcessMemory`（读不到 → 报错，进程不受影响）；
* 写 `0xCC` 与写回原字节都用 `WriteProcessMemory`；
* 于是**页的保护属性从头到尾没被改过**——`WriteProcessMemory` 在单次调用内部
  完成必要的处理，不会把目标页留在"被我改成可写"的状态里。

这也让异常处理器里那一步更简单：那里适合做系统调用，不适合改目标的内存属性。

## 异常上下文只做最小记录

向量化异常处理器（VEH）跑在**出错的线程**上，上下文很敏感：不能分配、
不能调外部 DLL、更不能长时间持锁。所以命中时只往一张**独立的**待处理表里
追加一条记录，事件由正常上下文（下一次 `pb_drain_events` / `pb_push_event`）取出并生成。

这样也避免了一个具体的自死锁：如果异常正好发生在我们持有 agent 全局状态锁的时候，
处理器再去抢同一把锁就会自己等自己。

另一个必须在这里做的动作是**把原字节写回去**：不恢复的话，目标会立刻在同一个
地址上再次触发 `int3`，形成无限循环。

## 目标自己的 `int3` 怎么办

**交回去。** 处理器只处理"表里登记过的地址"；不在表里的 `int3`
（目标的反调试、编译器的 `__debugbreak`、运行时断言）原样返回给系统，
走它自己的异常处理路径。

我们没有替目标决定"它自己的 `int3` 该怎么办"的权力——那是一个分析动作，
不是一个基础设施动作。

## 能力与审计

* 下断点/清断点都要 `breakpoint` 能力，闸门在 Rust 侧（脚本改不了）；
* **解一个不存在的断点必须报错**：静默成功会让调用方一直以为那边有断点；
* 重复下同一个地址**必须报错**：第二次记下来的"原字节"是 `0xCC`，
  解除之后会在内存里留下一个永久的 `0xCC`；
* 写回失败时把表项**放回去**，避免出现"表里没有、内存里还是 `0xCC`"的状态
  ——那种状态下调用方既解不掉也重下不了。

## 当前未落地

| 能力 | 状态 | 说明 |
|------|------|------|
| 单步 / 继续 / 暂停 | ⏳ | `pb_single_step` / `pb_continue` / `pb_pause` 仍是桩。它们需要"让目标的线程停下来"这个前提，而那超出 Pin 的能力范围（见上文）；先把**语义**定清楚再实现，不要做成"看起来像调试器" |
| 断点命中时的寄存器快照 | ⏳ | 目前事件只带地址与线程号；`CONTEXT` 里能拿到寄存器，但要不要在异常上下文里抓、抓了放哪（事件只有数字）需要先定 |
| 条件断点 | ⏳ | 依赖脚本：目前"条件"由脚本在收到命中事件后自己判断（命中即解除会让它变成轮询式重新下断点，语义上可行但不够优雅） |
| 硬件断点 | ⏳ 不做 | 只有 4 个且要抢目标的调试寄存器；没有公平的协调机制 |
