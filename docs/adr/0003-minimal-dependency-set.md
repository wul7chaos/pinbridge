# 0003. 依赖面压到极小

- 状态：已采纳
- 日期：2026-10-16
- 相关：[../dev/dependency-policy.md](../dev/dependency-policy.md)、[`deny.toml`](../../deny.toml)

## 背景

PinBridge 会**注入到别人的进程里**。它的依赖面直接等于攻击面，
而且每一次"顺手加个库"都会让"这个行为是哪一层引入的"更难回答。

同时有一个相反的诱惑：现代 Rust 生态里，"加个库"几乎总是比自己写快。

## 决策

运行期依赖只保留四个（Rust 侧）：

| 依赖 | 用途 |
|------|------|
| `serde` + `serde_json` | 协议、工具描述、summary、审计 |
| `thiserror` | 错误类型（零运行时代价） |
| `sha2` | 脚本溯源的跨语言哈希 |

Python 侧**运行期零依赖**。

并在 `deny.toml` 中**显式禁止**：

| 禁止 | 理由 |
|------|------|
| `reqwest` / `ureq` / `openssl-sys` | 一个能下传代码的调试工具，我们不希望它具备网络能力 |
| `tokio` | 不引入第二个运行时 |

**自己写的判据**：能在一个屏幕内读完 + 有测试覆盖 + 与领域强相关。
例子：varint/zigzag、`civil_from_days`、极简 JSON 字符串转义、Python 侧的只读字节流包装。

## 考虑过的替代方案

| 方案 | 为什么没选 |
|------|-----------|
| 用 `clap` 做 CLI | 我们的 CLI 只有 5 个子命令；手写解析 40 行，省一个不轻的依赖 |
| 用 `bitflags` 表示能力集 | 能力集有自定义的 JSON 形态（位图 + 名字），还是要自己写 serde；`from_bits` 掩码逻辑本来就只有几行 |
| 用 `chrono` 格式化时间戳 | 只需要"给人看的 UTC 时间"，20 行 `civil_from_days` 就够 |
| 用 `tokio` 做 IPC | Hub 是单进程控制面，std 线程 + 有界通道已经足够；`tokio` 会让"谁持有锁"更难推理 |
| 用 `zstd` 压缩轨迹 | 折叠 + delta 已经把 VMP 场景压到可接受；引入压缩库会把"证据不可读"变成新的问题（压缩后的部分损坏会连带毁掉整段） |

## 后果

**得到**：

* 依赖树极小 → 审计容易、供应链风险低、编译快；
* "哪些能力来自第三方"一目了然；
* 没有网络栈 → 不可能出现"不知不觉把数据发出去"的行为。

**付出**：

* 有些轮子要自己造（但都是有测试覆盖的小轮子）；
* 用户会觉得"连 clap 都不用"很怪 → 用本记录回答；
* 将来真有需求时，需要在 ADR 里写清代价，而不是顺手 `cargo add`。

## 复审条件

出现**无法用标准库解决**的具体问题时重新评估（例如需要真正的加密、
需要跨平台的路径规范化）。届时新写一条 ADR，写明"解决了哪个具体问题、
引入了哪些传递依赖、为什么没有更小的方案"。

**不接受"更现代/更流行"作为理由。**
