# 架构决策记录（ADR）

这里记录的**不是"我们做了什么"，而是"我们为什么没做别的"**。
每条决策都写了考虑过的替代方案与放弃它们的理由。

为什么这很重要：三个月后，一个人看到 `deny.toml` 里禁止 `tokio` 会觉得莫名其妙，
然后"顺手"去掉这行，引入一个第二运行时。ADR 的作用就是让这种改动
从"无意识的破坏"变成"需要先反驳一条记录"。

## 格式

```markdown
# NNNN. 标题

- 状态：已采纳 / 已废弃 / 被 NNNN 取代
- 日期：YYYY-MM-DD
- 相关：issue / PR / 其它 ADR

## 背景
## 决策
## 考虑过的替代方案
## 后果
```

**状态必须真实**：被推翻的记录不要删，标成"被 NNNN 取代"，
否则后来的人会重复讨论一遍。

## 什么时候需要新写一条

| 需要 ADR | 不需要 |
|----------|--------|
| 引入/移除依赖 | 修 bug |
| 改变协议 / 格式 / ABI | 加一个函数 |
| 改变权限模型或主体模型 | 重构（行为不变） |
| 引入新进程 / 新线程模型 / 新语言 | 文档更新 |
| 推翻已有 ADR | 加测试 |

写 ADR 的成本很低（半小时），但**推翻一个已经落地的架构决策成本极高**——
所以只要有犹豫，就写。
