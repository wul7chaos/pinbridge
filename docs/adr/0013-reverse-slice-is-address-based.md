# ADR 0013：反向切片是**地址级**的，不是数据流级的

- 状态：已接受（M3「反向切片」）
- 影响面：`crates/pinbridge-trace/src/slice.rs`、`crates/pinbridge-cli`（`pinbridge slice`）

## 背景

需求是「给定 OEP 候选，能列出影响它的写入链」。

天真的想法是"做数据流追踪"。但**我们必须先说清轨迹里有什么**，否则会给出
一条看着合理、实际推不出来的链——那比"答不出来"更糟，因为调用方会照着它改代码。

轨迹里实际有的（每条事件与它的 args 见 `docs/design/injection-points.md`）：

| 事件 | 能回答 | 不能回答 |
|------|--------|----------|
| `mem_write`（地址/长度/值） | 哪个地址在**哪一刻**被写成了什么 | 这个值**从哪来** |
| `mem_read`（地址/长度） | 哪个地址在哪一刻被读过 | 读到的东西被拿去做了什么 |
| `reg_write`（转移） | 控制流怎么走 | 数据怎么流 |
| `syscall_enter/exit` | 发生了哪个系统调用、参数是什么 | 指针指向的内容（离线读不到目标内存） |

**核心限制**：没有字节级污点传播时，一份轨迹**无法**回答"这段代码的字节是从
哪个缓冲区复制来的"。寄存器与 `memcpy` 会切断可追溯性：写入者放进去的值，
轨迹里只是 `args[2]` 的一个数字，与读出它的那条 `mem_read` 之间没有链接。

（字节级污点传播是下一项工作。这条 ADR 的价值之一，就是把它**需要补什么**
说清楚，而不是先用一个假的数据流图糊过去。）

## 决定

反向切片定义为**地址级（address-based）**，回答四个**可判定**的问题：

1. **谁写的**：所有与目标范围重叠的 `mem_write`（按序号升序）——
   地址、长度、写入的值、发生在第几条。
2. **被覆盖过几次**：同一字节被写多次时有几个写入者。多次写入是脱壳的常态
   （解密循环反复改写同一片内存），只报最后一个会把过程抹掉。
3. **谁读过**：与目标范围重叠的 `mem_read`——用以回答"这段字节在被执行前
   有没有被 OEP 之外的人读过"（例如校验、二次解密）。
4. **第一次被执行是什么时候**：第一条 `address` 落在目标范围内的事件。
   这是"OEP 真的跑起来"的时刻，与"被写出来"是两件事，缺一个都说不清故事。

### 三条诚实规则

- **探针没开就说没开**：如果整份轨迹里一条 `mem_write` 都没有，结论必须是
  「本轨迹无法回答『谁写的』（内存探针没开）」——不能报一个空的写入链，
  那会被读成"没人写过它"。
- **看不清就说不清**：`mem_read` / `mem_write` 的**值**只在探针能读到的情况下
  才有意义（`args[2]` 为 0 时可能是真的 0，也可能是"读不出"）。报告里对
  两者不作区分，但**明确标注**"读不出"的情形由探针侧的计数负责说明
  （见工具报告的「值读不出 N 条」）。
- **不猜数据流**：绝不因为"这次写入的值等于那个地址的内容"就画一条数据流边。
  相等不是因果，在脱壳场景里尤其如此（解密后的字节与密文字节常常有一半相同）。

### 为什么不是"从 OEP 反推控制流"

另一条路是反向走控制流图（谁 `call` 到这里）。它回答的是**另一个问题**
（"谁跳过来的"），且需要调用图与基本块边界，成本高得多。本 ADR 只做地址级切片；
控制流那半边已经在 `pinbridge calls` 里有了，两者**在报告里分开呈现**，
不混成一个数。

## 代价

- 复杂度：单遍扫描 + 按范围重叠判定，O(事件数)。
- 表达能力：只能回答"哪些地址被写成什么、谁读过、何时执行"。
  **不能**回答"这个值是从哪来的"——这是下一项（字节级污点）要补的洞。

## 备选方案（以及为什么不选）

| 方案 | 为什么没选 |
|------|-----------|
| 直接做数据流反向切片 | 现有事件模型里没有寄存器↔内存的数据来源关系，做出来只能是**猜测** |
| 只报"最后一个写入者" | 脱壳是**反复改写**同一片内存；只报最后一个等于把过程抹掉 |
| 把 `mem_read`/`mem_write` 的相等值当作数据流边 | 相等不是因果（密文与明文字节常常部分相同），会造出大量假链 |
| 用 `NtProtectVirtualMemory` 的参数解析出被改属性的范围 | 该调用的第一个参数是**指向范围结构体的指针**，离线读不到目标内存 ⇒ 只能报"发生过一次改属性"，报不出范围（报告里如实说明） |

## 验证

- `crates/pinbridge-trace/src/slice.rs` 的用例：
  按序的多个写入者都被列出（不是只留最后一个）；范围**部分重叠**也算写入者；
  第一次执行时刻与"被写入"分开；没有内存写入事件时结论是"探针没开"而不是空链；
  范围外的执行不计入。
- CLI：`pinbridge slice <FILE.pbt> --at 0x… [--len N]`，末行 `PB_SLICE …`。
